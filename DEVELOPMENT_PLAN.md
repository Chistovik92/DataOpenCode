# Статус и план развития opencode-port

Дата остановки текущего этапа: 2026-11-18.

## Готово

- Архив формата 2 содержит `manifest.json`, конфигурацию, выбранные секреты и экспортированные диалоги.
- Реализован аддитивный перенос провайдеров и моделей:
  - поддерживаются `provider` и `providers`;
  - локальные конфликтующие значения и настройки, не связанные с провайдерами, сохраняются;
  - `auth.json` дополняется только отсутствующими провайдерами;
  - существующие файлы `.opencode` не перезаписываются, добавляются только недостающие.
- Реализован перенос диалогов через штатные CLI-команды во всех четырёх направлениях:
  - V1 → V1;
  - V1 → V2;
  - V2 → V1;
  - V2 → V2.
- Для V1 ↔ V2 добавлены явные конвертеры JSON. Исходный transfer JSON сохраняется в metadata импортированной сессии для последующего восстановления исходных данных.
- Существующие session ID пропускаются; диалоги с совпадающими ID не объединяются и не перезаписываются.
- Дочерние диалоги импортируются после родительских.
- Поддержаны текст, reasoning, основные состояния инструментов, inline- и URL-вложения. Snapshot/diff-история не преобразуется в нативную историю целевой версии, но остаётся в сохранённом исходном JSON.
- V2 CLI 2.3.2 запускается с `--standalone`, чтобы не подключаться к фоновому сервису с другим окружением.
- Учитывается объектная пагинация V2 API: `cursor.next`.
- Добавлены резервные копии с GUID перед изменениями конфигурации, auth, `.opencode` и хранилища диалогов.
- Добавлены защиты:
  - ZIP path traversal, повторяющиеся пути, лимиты количества и размера элементов;
  - повреждённые config/auth/env/session JSON отклоняются;
  - auth/env и конвертация диалогов проверяются до изменения конфигурации;
  - значения секретов и stderr CLI не выводятся;
  - env записывается только в область User, без Machine и без изменения окружения последующего CLI;
  - UTF-8 сохраняет Unicode при экспорте диалогов;
  - `-DryRun` не изменяет config/auth/диалоги.

## Проверено

- `python -m unittest discover -s tests -v`: **17 тестов, OK**.
- Тесты используют подменённый OpenCode CLI и синтетические данные.
- Выполнен реальный изолированный тест с установленным OpenCode **2.3.2**:
  - V1 JSON сконвертирован и импортирован в V2;
  - диалог экспортирован обратно штатным CLI;
  - сохранены ID и два синтетических сообщения;
  - изолированная SQLite-база вернула `quick_check=ok`.
- Изменения опубликованы в `origin/main`; последний коммит реализации перед этим статусным коммитом: `1637acf`.

## Осталось сделать после возобновления

1. Обновить `README-opencode-port.md`, шапку скрипта и `RELEASE_NOTES.md`: они ещё частично описывают только перенос провайдеров и старое правило приоритета архива.
2. Проверить конвертеры на реальном V1 CLI 1.2.27, особенно V2 → V1. Сейчас это направление проверено только mock-тестами.
3. Расширить реальные изолированные проверки вложениями, tool/error/reasoning-сообщениями и parent/child-диалогами.
4. Добавить полный rollback при сбое в середине apply-фазы. Сейчас предпроверка предотвращает известные частичные изменения от повреждённых JSON, но ошибка CLI на позднем диалоге может оставить уже импортированные предыдущие диалоги и изменённые config/auth.
5. Усилить резервное копирование SQLite: использовать согласованный SQLite snapshot/online backup вместо независимого копирования `db`, `wal` и `shm`; проверить восстановление резервной копии.
6. Добавить лимиты размера/глубины JSON и покрытие ZIP cumulative-size/compression-ratio тестами.
7. Добавить тесты восстановления после сбоя второго и последующего импортов, точного Windows argv quoting и проверки ограничений env.
8. После завершения документации и проверок подготовить отдельный релиз; текущий опубликованный релиз `v1.0.0` не включает новую функциональность.

## Команды проверки

```bat
python -m unittest discover -s tests -v
```

Перед реальным импортом закрыть OpenCode Desktop и сначала выполнить `-DryRun`. Не использовать реальные секреты и диалоги в тестах.
