# Перенос своего провайдера OpenCode Desktop (Windows)

`opencode-port.ps1` собирает на компьютере A всё, что нужно для своего (кастомного)
провайдера моделей, и разворачивает это на компьютере B.

## Что переносится и откуда берётся

OpenCode (и CLI, и desktop) не хранит провайдеров в своей базе — он читает их из
файлов и окружения. Поэтому переносить надо два места:

| Данные | Путь на Windows | Зачем |
|---|---|---|
| Конфиг провайдеров и моделей | `%USERPROFILE%\.config\opencode\opencode.json` / `opencode.jsonc` | `provider`, `disabled_providers`, модели, `npm`, `options.baseURL`, headers |
| Локальные агенты/плагины проекта | `%USERPROFILE%\.config\opencode\.opencode\` (если есть) | свои агенты, команды, плагины |
| Ключ API провайдера | `%USERPROFILE%\.local\share\opencode\auth.json` | `{"providerID": {"type":"api","key":"..."}}` |
| Переменные окружения (опционально) | реестр пользователя / машины | если провайдер читает ключ из env (`{env:VAR}` / `env: [...]`) |

Пути `config`/`data` учитывают `XDG_CONFIG_HOME`, `XDG_DATA_HOME` и `OPENCODE_CONFIG_DIR`,
как это делает сам sidecar desktop-приложения.

Сессии, история чатов и настройки интерфейса (`%APPDATA%\ai.opencode.desktop`) **не**
переносятся намеренно — они не нужны для работы провайдера и тянут за собой локальные пути.
Если нужна только «чистая» настройка провайдера на новом ПК — этого достаточно.

## Быстрый старт

Двойной клик по `opencode-port.cmd` — появится меню:

1. Экспорт — создаёт `opencode-port-<ИМЯ-ПК>-<дата>.zip`
2. Импорт — разворачивает архив (OpenCode Desktop должен быть закрыт)
3. Проверка — показывает, что попадёт в архив, без создания файла

Из консоли:

```bat
:: на компьютере A
opencode-port.cmd export
opencode-port.cmd export -Out D:\share\my-provider.zip
opencode-port.cmd export -Secrets All -Env AISTAR_API_KEY

:: на компьютере B (OpenCode Desktop закрыт)
opencode-port.cmd import -Zip D:\share\my-provider.zip
opencode-port.cmd import -Zip D:\share\my-provider.zip -SetEnv -OverwriteEnv
opencode-port.cmd import -Zip D:\share\my-provider.zip -DryRun
```

Параметры экспорта:

- `-Secrets Auth` (по умолчанию) — включить `auth.json` с ключами API
- `-Secrets All` — `auth.json` + переменные окружения из `-Env`
- `-Secrets None` — только конфиг, без секретов (ключ введёте на месте)

Параметры импорта:

- `-SetEnv` — записать переменные окружения из архива
- `-OverwriteEnv` — перезаписать уже существующие переменные (иначе они сохраняются)
- `-DryRun` — показать план изменений, ничего не записывая

## Как устроен импорт

1. Проверяет, что OpenCode Desktop не запущен (иначе sidecar перезапишет конфиг из памяти).
2. Распаковывает архив во временную папку.
3. Конфиг **сливает** с уже существующим: провайдеры, модели и прочие поля из архива
   имеют приоритет, остальные локальные настройки (тема, агенты, провайдеры, которых
   не было в архиве) сохраняются. Понимает JSONC — комментарии `//`, `/* */` и висячие
   запятые. Комментарии при слиянии не сохраняются (оригинал остаётся в `.bak`).
   Результат пишется в файл с наивысшим приоритетом загрузки (`opencode.jsonc`, если
   он существует, иначе `opencode.json`) — так старый файл не затенит изменения.
4. `auth.json` сливает по провайдерам и ограничивает права файла текущему пользователю.
5. Переменные окружения добавляет только при `-SetEnv`; существующие не трогает без
   `-OverwriteEnv`.
6. Перед изменением каждого файла делает копию `*.bak` (с датой в имени).

Обработка ошибок: повреждённый архив, чужой zip или неизвестный формат отклоняются
с понятным сообщением; ничего не меняется до успешного чтения manifest. Если конфиг в
архиве неразборчив даже как JSONC — он копируется как есть (без слияния), чтобы не
потерять данные.

## Безопасность

Архив с `-Secrets Auth/All` содержит действующий API-ключ в открытом виде.
Передавайте его по защищённому каналу и удаляйте после импорта. Если нужен перенос без
ключей — используйте `-Secrets None`, а ключ введите на машине B вручную: в desktop
`Настройки → Модели → +` либо в `auth.json`.

## Если провайдер пропал после перезапуска

- Проверьте, что `opencode.json` лежит именно в `%USERPROFILE%\.config\opencode\`
  (или в каталоге из `OPENCODE_CONFIG_DIR`).
- Проверьте, что провайдер не выключен: `"disabled_providers"` не должен содержать его id.
- Desktop-приложение перезаписывает конфиг при своих операциях из UI, поэтому импорт
  делайте при закрытом приложении.
- Провайдер с `"npm": "@ai-sdk/openai-compatible"` при первом запуске подтягивает пакет
  из npm — нужен интернет.
