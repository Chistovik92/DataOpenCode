# OpenCode Port — подробная документация

> Краткий обзор и быстрый старт — в [`README.md`](README.md).

`opencode-port.ps1` собирает на компьютере A всё, что нужно для своего (кастомного)
провайдера моделей, ключей API и диалогов, и разворачивает это на компьютере B —
аддитивно, не удаляя и не перезаписывая существующие локальные настройки, файлы и
записи с совпадающими ID.

## Что переносится и откуда берётся

OpenCode (и CLI, и desktop) не хранит провайдеров в своей базе — он читает их из
файлов и окружения. Поэтому переносить надо два места:

| Данные | Путь на Windows | Зачем |
|---|---|---|
| Конфиг провайдеров и моделей | `%USERPROFILE%\.config\opencode\opencode.json` / `opencode.jsonc` | `provider` / `providers`, `disabled_providers`, модели, `npm`, `options.baseURL`, headers |
| Локальные агенты/плагины проекта | `%USERPROFILE%\.config\opencode\.opencode\` (если есть) | свои агенты, команды, плагины |
| Ключ API провайдера | `%USERPROFILE%\.local\share\opencode\auth.json` | `{"providerID": {"type":"api","key":"..."}}` |
| Переменные окружения (опционально) | реестр пользователя | если провайдер читает ключ из env (`{env:VAR}` / `env: [...]`) |
| Диалоги (сессии) | хранилище OpenCode | переносятся через штатные CLI-команды `export`/`import` |

Пути `config`/`data` учитывают `XDG_CONFIG_HOME`, `XDG_DATA_HOME` и `OPENCODE_CONFIG_DIR`,
как это делает сам sidecar desktop-приложения.

Настройки интерфейса desktop (`%APPDATA%\ai.opencode.desktop`) **не** переносятся
намеренно — они не нужны для работы провайдера и тянут за собой локальные пути.

## Быстрый старт

Двойной клик по `opencode-port.cmd` — появится меню:

1. Экспорт — создаёт `opencode-port-<ИМЯ-ПК>-<дата>.zip`
2. Импорт — разворачивает архив (OpenCode Desktop должен быть закрыт)
3. Проверка — показывает, что попадёт в архив, без создания файла

Из консоли:

```bat
:: на компьютере A
opencode-port.cmd export
opencode-port.cmd export -Out D:\share\my-provider.zip
opencode-port.cmd export -Secrets All -Env AISTAR_API_KEY
opencode-port.cmd export -SkipSessions

:: на компьютере B (OpenCode Desktop закрыт)
opencode-port.cmd import -Zip D:\share\my-provider.zip
opencode-port.cmd import -Zip D:\share\my-provider.zip -SetEnv -OverwriteEnv
opencode-port.cmd import -Zip D:\share\my-provider.zip -DryRun
opencode-port.cmd import -Zip D:\share\my-provider.zip -SessionDirectory D:\work
```

Параметры экспорта:

- `-Secrets Auth` (по умолчанию) — включить `auth.json` с ключами API
- `-Secrets All` — `auth.json` + переменные окружения из `-Env`
- `-Secrets None` — только конфиг, без секретов (ключ введёте на месте)
- `-SkipSessions` — не экспортировать диалоги

Параметры импорта:

- `-SetEnv` — записать переменные окружения из архива
- `-OverwriteEnv` — перезаписать уже существующие переменные (иначе они сохраняются)
- `-SessionDirectory` — каталог для импортируемых диалогов (по умолчанию текущий)
- `-DryRun` — показать план изменений, ничего не записывая

## Как устроен импорт

1. Проверяет, что OpenCode Desktop не запущен (иначе sidecar перезапишет конфиг из памяти).
2. Безопасно распаковывает архив во временную папку (с проверкой path traversal и лимитов).
3. Проверяет config, auth, env и диалоги архива и локальные config/auth **до** любого изменения.
4. Конфиг **сливает аддитивно**: провайдеры и модели из архива добавляются, локальные
   конфликтующие значения и настройки, не связанные с провайдерами (тема, `permission` и
   т. п.), сохраняются. Поддерживаются `provider` и `providers`. Понимает JSONC —
   комментарии `//`, `/* */` и висячие запятые. Результат пишется в файл с наивысшим
   приоритетом загрузки (`opencode.jsonc`, если он существует, иначе `opencode.json`).
5. `auth.json` дополняется только отсутствующими провайдерами; права файла ограничиваются
   текущему пользователю.
6. Переменные окружения применяются только при `-SetEnv`; существующие не трогаются без
   `-OverwriteEnv`; записываются только в область User.
7. Диалоги импортируются через штатные CLI-команды. Существующие session ID пропускаются;
   родительские диалоги импортируются раньше дочерних. Для V1↔V2 выполняется конвертация,
   исходный JSON сохраняется в metadata.
8. Перед изменением каждого файла и хранилища диалогов делает копию `*.bak`.

Обработка ошибок: повреждённый архив, чужой zip, неизвестный формат, повреждённые
config/auth/env/session JSON отклоняются с понятным сообщением; ничего не меняется до
успешной предпроверки. Значения секретов и stderr CLI не выводятся.

## Безопасность

Архив с `-Secrets Auth/All` содержит действующий API-ключ в открытом виде.
Передавайте его по защищённому каналу и удаляйте после импорта. Если нужен перенос без
ключей — используйте `-Secrets None`, а ключ введите на машине B вручную: в desktop
`Настройки → Модели → +` либо в `auth.json`.

## Если провайдер пропал после перезапуска

- Проверьте, что `opencode.json` лежит именно в `%USERPROFILE%\.config\opencode\`
  (или в каталоге из `OPENCODE_CONFIG_DIR`).
- Проверьте, что провайдер не выключен: `"disabled_providers"` не должен содержать его id.
- Desktop-приложение перезаписывает конфиг при своих операциях из UI, поэтому импорт
  делайте при закрытом приложении.
- Провайдер с `"npm": "@ai-sdk/openai-compatible"` при первом запуске подтягивает пакет
  из npm — нужен интернет.
